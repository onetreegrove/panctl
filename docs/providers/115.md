# 115 Provider 实现方案

本文档基于 `tmp/` 中 Alist 的 115 相关实现整理，目标是把 115 网盘作为 `pan-cli` 的第一个 provider 落地。参考代码主要来自：

- `tmp/drivers/115`：Cookie/二维码登录体系，文件管理能力完整，含离线任务和上传。
- `tmp/drivers/115_open`：开放接口体系，基于 access token / refresh token，上传流程更标准。
- `tmp/drivers/115_share`：分享链接只读访问，支持列目录和下载。

## 结论

第一版优先实现 `tmp/drivers/115` 这条路线，也就是 **Cookie/QR 登录 + SheltonZhu/115driver**。原因：

1. 能力覆盖最完整：列目录、下载、创建目录、移动、复制、重命名、删除、上传、离线任务都已有参考实现。
2. 登录门槛适合 CLI：支持 Cookie 导入，也支持二维码登录换取 `UID/CID/SEID/KID`。
3. 离线任务只在这条路线里有完整参考。

`115_open` 作为第二阶段补充，用于支持 refresh token 登录和更稳定的开放接口上传。`115_share` 作为第三阶段补充，用于只读访问分享链接，不混进主账号文件系统能力。

## 入口

统一入口：

```bash
pan ls 115:/电影
pan login 115 qr
pan offline 115 add <url> --to 115:/下载
```

专属入口：

```bash
115-cli ls /电影
115-cli login qr
115-cli offline add <url> --to /下载
```

`115-cli <cmd>` 等价于 `pan --provider 115 <cmd>`。

## Capabilities

第一版能力声明：

```json
{
  "provider": "115",
  "capabilities": {
    "path_lookup": true,
    "list": true,
    "search": false,
    "mkdir": true,
    "rename": true,
    "move": true,
    "copy": true,
    "remove": true,
    "download": true,
    "upload": false,
    "offline_task": true,
    "share": false,
    "recycle_bin": false,
    "rapid_upload": false,
    "cross_transfer": false
  }
}
```

说明：

1. `search=false`：Alist 的 115 driver 没有直接提供搜索参考，第一版先不承诺。
2. `upload=false`：上传实现复杂，涉及 SHA1、秒传、OSS token、分片和 callback，放到第二阶段。
3. `rapid_upload=false`：即使上传内部会先尝试秒传，也不先暴露成公共 capability。
4. `share=false`：分享链接访问走独立 share mode，不在第一版主 provider 声明。

第二阶段完成上传后，把 `upload` 标记为 `true`。如果单独提供 `115-cli rapid-upload`，再考虑 `rapid_upload=true`。

## 认证设计

### 凭证模型

115 Cookie 最小凭证由四个字段组成：

```text
UID=<uid>;CID=<cid>;SEID=<seid>;KID=<kid>
```

内部保存为结构化字段，输出和日志只允许脱敏：

```json
{
  "uid": "123***789",
  "has_cid": true,
  "has_seid": true,
  "has_kid": true
}
```

凭证由根项目 `internal/credential` 管理，优先写入系统钥匙串，文件回退时权限必须是 `0600`。

### Cookie 登录

```bash
115-cli login cookie
```

输入方式：

1. 交互粘贴 Cookie。
2. `--cookie <value>`，仅供本地手动使用，不建议 Agent 使用。
3. 从 stdin 读取：`printf '%s' "$COOKIE" | 115-cli login cookie --stdin`。

流程：

1. 使用 `driver115.Credential.FromCookie` 解析 Cookie。
2. `ImportCredential` 注入客户端。
3. 调用 `LoginCheck` 验证。
4. 成功后保存结构化凭证。

### QR 登录

用户侧命令仍保持两段式：

```bash
115-cli login qr --json
115-cli login wait <session_id> --json
```

Alist 参考实现里使用的是已有 `QRCodeToken` 调用 `QRCodeLoginWithApp`。我们的 CLI 需要补齐“创建 QR session”的前半段：

1. `login qr` 调用 115driver 的 QR session 创建能力，拿到二维码 token、登录 URL、过期时间。
2. 将 session 缓存在本地临时目录，例如 `$TMPDIR/pan-cli/115-login/<session_id>.json`，权限 `0600`。
3. `login wait` 读取 session，调用 `QRCodeLoginWithApp` 轮询确认。
4. 成功后生成 `UID/CID/SEID/KID` Cookie 并保存。

默认 QR source 使用 `linux` 或 `web`。参考 Alist 可选值：

```text
web, android, ios, tv, alipaymini, wechatmini, qandroid, linux
```

CLI 第一版只暴露：

```bash
115-cli login qr --source linux
```

## 文件模型

115 返回对象需要转换为公共 `contract.FileInfo`：

```json
{
  "id": "123456789",
  "name": "demo.mp4",
  "type": "file",
  "path": "/电影/demo.mp4",
  "size": 1048576,
  "sha1": "ABCDEF...",
  "pick_code": "ecjq9ichcb40lzlvx",
  "thumb_url": "https://...",
  "created_at": "2026-06-01T12:00:00+08:00",
  "updated_at": "2026-06-01T12:00:00+08:00",
  "provider": "115",
  "raw": {}
}
```

内部必须保留 `pick_code`，下载接口依赖它。对外 JSON 可以展示 `pick_code`，但后续如果确认它具备敏感性，再改为仅 `--verbose-json` 输出。

目录的 `type` 为 `dir`，`id` 使用 115 的 category/file id。

## Target 与路径解析

115 第一版支持两种 target：

1. ID：`123456789`
2. 绝对路径：`/电影/demo.mp4`

统一入口支持：

```bash
pan ls 115:/电影
```

路径解析策略：

1. 根目录 ID 固定为 `0`。
2. 遇到 ID target 时直接构造 lightweight object，再按命令需要补充 `getFileInfo`。
3. 遇到路径 target 时从根目录逐级 `List` 查找。
4. 为减少 API 请求，`internal/resolver` 可加入短期缓存：`provider/profile/path -> id`。
5. 找不到路径时映射为 `NOT_FOUND`。

Alist 的 115 driver 主要按 ID 工作；路径解析是 CLI 需要新增的层。

## 列目录与分页

Alist 的 `getFiles` 会循环拉完整目录。CLI 需要同时支持“单页”和“自动全量”：

```bash
115-cli ls /电影 --page 1 --limit 100 --json
115-cli ls /电影 --all --json
```

默认行为：

1. 人类模式默认取第一页，显示分页提示。
2. `--json` 默认取第一页，并返回 `pagination`。
3. Agent 需要全量时使用 `--all`，或根据 `pagination.has_more` 自行继续请求。

115 API 使用 `offset + limit`，CLI 对外使用 `page + limit`：

```text
offset = (page - 1) * limit
```

参考实现中的重要参数：

```text
aid=1
cid=<dir_id>
show_dir=1
limit=<limit>
offset=<offset>
format=json
record_open_time=1
```

`limit` 不得超过 115 driver 的 `MaxDirPageLimit`。

## 下载设计

```bash
115-cli download /电影/demo.mp4 --json
115-cli download /电影/demo.mp4 --output ./demo.mp4
```

流程：

1. 解析 target，确认是文件。
2. 获取对象 `pick_code`。
3. 调用 `DownloadWithUA(pickCode, userAgent)`。
4. 未指定 `--output` 时输出下载 URL 和必要 header。
5. 指定 `--output` 时由公共 `internal/transfer` 负责下载、进度、断点续传。

JSON 示例：

```json
{
  "status": "ok",
  "data": {
    "id": "123456789",
    "name": "demo.mp4",
    "url": "https://...",
    "headers": {
      "User-Agent": "Mozilla/5.0 ..."
    },
    "expires_at": null
  },
  "meta": {
    "provider": "115",
    "profile": "default",
    "request_id": "req_20260601_115001"
  }
}
```

## 文件变更命令

变更命令第一版支持单个或多个 target：

```bash
115-cli mkdir /电影 新目录
115-cli mv /电影/a.mp4 --to /归档
115-cli cp /电影/a.mp4 --to /备份
115-cli rename /电影/a.mp4 b.mp4
115-cli rm /电影/a.mp4
```

设计要求：

1. 命令执行前解析所有 target，避免部分解析失败后已经执行变更。
2. 多 target 执行时返回逐项结果。
3. 对 115 API 无法提供事务的命令，失败时不做自动回滚，只在 JSON 中标明成功/失败项。
4. 重名、目标不存在、权限问题分别映射到 `CONFLICT`、`NOT_FOUND`、`PERMISSION_DENIED`。

## 离线任务

115 离线任务是第一版特殊能力。

```bash
115-cli offline add <url> --to /下载 --json
115-cli offline list --json
115-cli offline wait <hash-or-gid> --json
115-cli offline delete <hash-or-gid> [--delete-files] --json
```

参考 Alist：

```go
client.ListOfflineTask(0)
client.AddOfflineTaskURIs(uris, dstDirID, driver115.WithAppVer(appVer))
client.DeleteOfflineTasks(hashes, deleteFiles)
```

任务模型统一输出：

```json
{
  "gid": "task_hash_or_gid",
  "name": "demo.mp4",
  "status": "running",
  "progress": 42.5,
  "size": 1048576,
  "file_id": "123456789",
  "raw": {}
}
```

`offline wait` 策略：

1. 默认每 5 秒轮询一次。
2. 默认超时 2 小时，可通过 `--timeout` 覆盖。
3. 完成后返回最终任务对象。
4. 失败、取消、超时分别映射到 `REMOTE_ERROR` 或 `NETWORK_ERROR`。

## 上传设计（第二阶段）

上传不放在第一阶段交付，但先按 Alist 方案设计好边界。

```bash
115-cli upload ./demo.mp4 --to /电影 --json
```

Cookie 路线参考 `tmp/drivers/115`：

1. 检查 `UploadAvailable`。
2. 文件大小不能超过 `UploadMetaInfo.SizeLimit`。
3. 计算前 128 KiB SHA1 作为 `pre_hash`。
4. 计算全文件 SHA1。
5. 调用 `ApiUploadInit` 尝试秒传。
6. 如返回 `Status == 7`，根据 `SignCheck` 指定范围计算二次 SHA1，再重试。
7. 秒传成功后通过 `pick_code` 或 file id 查询新文件。
8. 秒传失败后获取 OSS 参数。
9. 小于等于 10 MiB 使用普通 OSS 上传。
10. 大文件使用 OSS multipart 上传。

`115_open` 上传流程更清晰，可作为重构参考：

1. `UploadInit`
2. `UploadGetToken`
3. OSS single/multipart upload
4. callback 完成

上传实现要求：

1. 支持 ctx cancel。
2. 支持进度输出到 `stderr`。
3. 支持 SHA1 缓存，避免重复读取大文件。
4. 分片上传限制并发，避免内存暴涨。
5. OSS token 过期需要刷新。

## 分享链接（第三阶段）

`tmp/drivers/115_share` 支持只读分享访问：

```bash
115-cli share ls <share-url>
115-cli share download <share-url> --file-id <id>
```

实现点：

1. 从分享 URL 解析 `share_code` 和 `receive_code`。
2. 调用 `ApiShareSnap` 列目录。
3. 调用 `ApiDownloadGetShareUrl` 获取下载链接。
4. 不支持 mkdir/move/rename/copy/remove/upload。

分享链接不要混入主账号文件树。它是 `share` 特殊命令，不参与 `pan ls 115:/path`。

## App Version 与限速

115 离线任务和上传依赖 app version。Alist 参考实现：

1. 默认版本 `27.0.5.7`。
2. 调用 `ApiGetVersion` 获取当前版本。
3. 选择 `AppName == "win"` 的版本。
4. 获取失败时回退默认版本。

CLI 实现：

1. 启动 provider 时异步/懒加载 app version。
2. 缓存到 profile metadata，缓存 24 小时。
3. 失败时使用默认值并输出 verbose 日志。

限速：

```bash
115-cli --rate 2 ls /
```

内部使用 `rate.Limiter`，默认每秒 2 个 API 请求。批量命令和分页必须走同一个 limiter。

## 错误映射

Provider 层要把 115driver 原始错误映射到公共错误码：

| 场景 | 公共错误码 |
| --- | --- |
| Cookie 缺失 | `AUTH_REQUIRED` |
| Cookie 解析失败 | `AUTH_REQUIRED` |
| `LoginCheck` 失败或登录过期 | `AUTH_EXPIRED` |
| `ErrNotExist` | `NOT_FOUND` |
| 重名、重复任务 | `CONFLICT` |
| 限流、风控临时失败 | `RATE_LIMITED` |
| 网络超时、DNS、连接失败 | `NETWORK_ERROR` |
| 115 API 业务失败 | `REMOTE_ERROR` |
| 上传超出大小 | `UNSUPPORTED_CAPABILITY` 或 `REMOTE_ERROR`，按错误语义决定 |

错误 detail 必须脱敏，不得包含 Cookie、下载 URL 中的敏感 query、Authorization header。
